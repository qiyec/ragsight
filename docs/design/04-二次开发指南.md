# 二次开发指南

这篇讲**想加功能时改哪里、按什么顺序改、容易漏什么**。

每个改动都给了具体步骤。步骤里标 ⚠️ 的地方是踩过坑的。

---

## 改之前先看这条

加任何东西之前先问一句：**它需要外部依赖吗？**

| 情况 | 放哪 |
|---|---|
| 纯计算，只用 JDK | `ragsight-domain` |
| 要读文件、调接口、连数据库 | `ragsight-infrastructure` |

判断错了 `mvn verify` 会失败（有架构测试拦着），
但先说清楚能省一轮返工。

## 1. 加一种切分策略

**改 3 个文件。**

### 第 1 步：写实现

`ragsight-domain/src/main/java/cn/qiyec/ragsight/domain/knowledge/chunking/`

新建 `SemanticChunkingStrategy.java`：

```java
public final class SemanticChunkingStrategy implements ChunkingStrategy {

    private final int maxChunkSize;

    public SemanticChunkingStrategy(int maxChunkSize) {
        if (maxChunkSize <= 0) {
            throw new IllegalArgumentException("maxChunkSize 必须为正数，实际为 " + maxChunkSize);
        }
        this.maxChunkSize = maxChunkSize;
    }

    @Override
    public String name() {
        return "semantic";          // 稳定且唯一，用于报告和日志
    }

    @Override
    public String describe() {
        return "语义切分 max=" + maxChunkSize;   // 要能区分不同参数
    }

    @Override
    public List<Chunk> chunk(Document document) {
        List<String> texts = 你的切分逻辑(document.content());
        return document.toChunks(texts);   // ⚠️ 必须走这个方法
    }
}
```

⚠️ **必须用 `document.toChunks(texts)`，不要自己 `new Chunk(...)`。**

因为它统一处理两件事：序号从 0 连续编号、空白片段被剔除。
自己 new 的话，序号可能不连续，报告里的 `文档#序号` 就对不上了。

⚠️ **`describe()` 要带上参数。** 同一个类配不同参数是两个不同的实验，
报告里必须能区分。只写 `"semantic"` 的话，512 和 256 两行看起来一样。

⚠️ **不许用随机数。** 同样的文档切两次必须得到同样的结果，
否则诊断结论不可复现。架构测试会拦 `Random`。

### 第 2 步：写成可用的实验方案

`ragsight-application/.../ExperimentPlan.java` 加一个静态方法：

```java
public static ExperimentPlan semanticDefault(int topK) {
    return new ExperimentPlan("semantic", "语义切分",
            new SemanticChunkingStrategy(512), topK);
}
```

### 第 3 步（可选）：放进默认对比

如果希望 `diagnose` 默认就对比它，改 `chunkingBaselines()`：

```java
public static List<ExperimentPlan> chunkingBaselines(int topK) {
    return List.of(
            recursiveDefault(topK),
            recursiveCoarse(topK),
            fixedWindowDefault(topK),
            semanticDefault(topK));      // 加这行
}
```

⚠️ 加了会让实验次数变多。每加一个切分方案，
就是"切分数 × 召回数"次实验，跑得更慢。

### 第 4 步：写测试

在 `ragsight-domain/src/test/.../chunking/` 下加测试。至少要覆盖：

- 参数不合法时构造失败
- 序号从 0 连续
- 最后一片覆盖到文档末尾（不然尾部内容永远检索不到）
- **相同输入两次结果一样**（可复现）

## 2. 加一种召回方式

**改 3 个文件**，比切分多一步（要在工厂里注册）。

### 第 1 步：写实现

放哪取决于**需不需要外部依赖**：

- 纯算法（像 BM25 那样）→ `domain/retrieval/`
- 要调接口或连库 → `infra/retriever/`

在 `infra/retriever/` 新建 `TitleRetriever.java`：

```java
public final class TitleRetriever implements Retriever {

    private final List<Chunk> chunks;

    public TitleRetriever(List<Chunk> chunks) {
        this.chunks = List.copyOf(chunks);
    }

    @Override
    public List<ScoredChunk> retrieve(String query, int topK) {
        // ... 你的召回逻辑
        return result;
    }
}
```

⚠️ **返回的 `rank` 必须从 1 开始连续编号。**
融合（RRF）用的是排名，跳号会让融合算错。

⚠️ **同分时要有固定的次级排序键**（比如片段标识）。
"保持原顺序"不行——原来的顺序可能本身就不稳定，结果就不可复现了。

⚠️ **`RetrievalSource` 要标对。** 报告靠它区分"是召回没召到"
还是"重排把好的排下去了"。新加的话考虑在枚举里加一个值，
而不是复用 `VECTOR`。

### 第 2 步：加进配置枚举

`ragsight-application/.../RetrieverConfig.java`：

```java
public enum Kind {
    VECTOR_ONLY("仅向量召回"),
    KEYWORD_ONLY("仅关键词召回"),
    HYBRID_RRF("向量+关键词 融合"),
    TITLE_ONLY("仅标题召回");          // 加这个

    private final String label;
    // ...
}
```

再加一个工厂方法：

```java
public static RetrieverConfig titleOnly() {
    return new RetrieverConfig("title", "仅标题召回", Kind.TITLE_ONLY);
}
```

并加进 `standardBaselines()`（如果想默认对比）。

### 第 3 步：在工厂里接上 ⚠️ 最容易漏

`ragsight-infrastructure/.../CompositeRetrieverFactory.java`：

```java
Retriever base = switch (config.kind()) {
    case VECTOR_ONLY -> buildVectorRetriever();
    case KEYWORD_ONLY -> buildKeywordRetriever();
    case HYBRID_RRF -> buildHybridRetriever(topK);
    case TITLE_ONLY -> buildTitleRetriever();    // 加这个
};
```

**漏了这步编译不过**，因为 `switch` 是穷尽的——这是用枚举的一个好处。

### 第 4 步：写测试

- 能召回正确的片段
- `rank` 从 1 连续
- `topK` 截断
- 空语料返回空
- 两次结果一致

## 3. 换向量模型

**不用改代码**，改参数就行。因为已经有一个通用适配器了。

```bash
--embedding-base-url https://api.siliconflow.cn/v1
--embedding-model    BAAI/bge-m3
```

Key 从环境变量读（默认 `RAGSIGHT_API_KEY`，可用 `--api-key-env` 改）。

**如果目标接口不是 OpenAI 兼容格式**，才需要写新适配器：

在 `infra/embedding/` 新建一个类实现 `domain/retrieval/EmbeddingModel`：

```java
public final class SomeOtherEmbedding implements EmbeddingModel {

    @Override
    public int dimension() { ... }

    @Override
    public List<float[]> embed(List<String> texts) {
        // ⚠️ 返回顺序必须和输入严格一致
    }
}
```

然后在 `DiagnoseCommand` 里选择用哪个（照着现有的
`if (embeddingModel != null)` 那段加分支）。

⚠️ **批量接口不要写成逐条调用。** 真实接口有固定开销
（网络往返、鉴权），逐条会慢一个数量级。

⚠️ **返回条数和请求条数不一致时要报错，不能硬凑。**
错位是静默的灾难——检索结果看起来正常，语义全错。

## 4. 换向量存储（比如换成 pgvector）

**改 1 个文件 + 1 处装配。**

新建一个类实现 `domain/retrieval/VectorIndex`：

```java
public final class PgVectorIndex implements VectorIndex {

    @Override
    public void rebuild(List<Chunk> chunks, List<float[]> vectors, int dimension) {
        // ⚠️ 是"覆盖"不是"追加"
    }

    @Override
    public List<ScoredChunk> search(float[] queryVector, int topK) { ... }

    @Override
    public int size() { ... }

    @Override
    public int dimension() { ... }
}
```

⚠️ **`rebuild` 必须是替换语义。** 诊断要反复在同一份语料上用不同
切分重建索引，如果是追加，上一轮实验的数据会混进这一轮的结果里。

⚠️ **维度不匹配要报错，并给出可能原因。** 现有实现的消息里带了
"通常是换 embedding 模型后忘记重建索引"，这种提示能省很多排查时间。

然后在 `DiagnoseCommand` 里把 `InMemoryVectorIndex::new` 换成你的实现。

## 5. 加一个评估指标

**改 1 个文件。**

在 `domain/evaluation/` 新建：

```java
public record HitRate(int k) implements Metric {

    @Override
    public String name() {
        return "HitRate@" + k;      // 报告里显示的名字
    }

    @Override
    public double score(GoldenCase testCase, RetrievedEvidence evidence) {
        if (testCase.isNegative()) {
            return Double.NaN;      // ⚠️ 负样本要返回 NaN
        }
        // ... 你的算法
    }
}
```

⚠️ **负样本必须返回 `NaN`**，表示"不参与平均"。
如果返回 0，负样本会拉低分数；返回 1，会虚高。
`Metric.scoreAll()` 的默认实现会跳过 `NaN`。

至于负样本该返回 `NaN` 还是满分，取决于指标类型：

| 指标类型 | 负样本应该 | 为什么 |
|---|---|---|
| 召回类（`Recall@k`） | 返回 `1.0` | 没有该找的东西，就不存在"漏找" |
| 排序类（`MRR`、`nDCG`） | 返回 `NaN` | 排序质量对负样本没有定义 |

⚠️ **指标实现要手算验证。** 不要拿实现自己的输出当预期值——
那样只能证明"代码没改"，证明不了"算得对"。
现有三个指标的测试里每个用例都写了推导过程，照着写。

### 加进报告

`DiagnosisEngine.runExperiment()` 里有一行：

```java
List<Metric> metrics = List.of(new RecallAtK(topK), new MRR(topK), new NDCG(topK));
```

加进去就行，报告会自动多一列。

## 6. 支持新的文档格式（比如 PDF）

**改 1 个文件。**

不用动 `DocumentReader` 接口——它的实现是"读目录"，
里面按扩展名分发。所以给 `DirectoryDocumentReader` 加 PDF 处理：

1. 在 `DEFAULT_EXTENSIONS` 里加 `.pdf`
2. 在 `readOne()` 里按扩展名选解析方式
3. 引入 PDFBox 依赖，**加在 `ragsight-infrastructure/pom.xml`**

⚠️ **PDFBox 不能加到 domain。** 它是第三方库，
加了架构测试会失败。

⚠️ **解析失败只跳过那一个文件，并记日志。**
不要让一个坏文件把整批都搞崩。

## 7. 改结论规则

**改 1 个文件**：`ragsight-application/.../DiagnosisEngine.java`

规则都在 `DiagnosisEngine` 里，方法名分别是：

| 方法 | 管什么 |
|---|---|
| `deriveFindings()` | 主入口：召回够不够、排序够不够，再调用下面三个 |
| `deriveRerankFindings()` | 重排有没有用（用"同切分一加一不加"的配对方案比） |
| `deriveChunkingFindings()` | 切分有没有影响（只比"都不加重排"的方案） |
| `deriveRetrieverFindings()` | 换召回有没有收益 |

改的时候注意：

⚠️ **规则必须是确定性的，不许调大模型。**
同一份输入必须得到同一份报告。用户要拿报告去改生产配置，
结论不稳定他不敢用。

⚠️ **每条结论都要能对应到报告里的具体数字。**
"效果不好"这种话没有价值，"Recall@5 = 0.55，约 45% 的期望片段
没进候选"才有。

⚠️ **阈值都提到了常量**（`NOTABLE_DELTA` 等），加新规则时也用常量，
不要在方法里写魔法数字。

⚠️ **别把没验证的因果说成因果。** 现有代码里有一处专门的提醒：

```
⚠ 但别急着下结论：片段切得越大，一个片段里装的内容越多，
命中率天然就越高——这不一定说明检索变好了。
```

这类"看起来是改善，其实可能是假象"的情况要主动指出来，
否则用户会被数字误导着把片段越切越大。

## 8. 改报告格式

**改 1 个文件**：`ragsight-cli/.../ReportRenderer.java`

⚠️ **渲染层只负责展示，不许做判断。**
所有结论都是引擎推出来的。在渲染层加判断会导致
同一份数据可能显示出两种结论。

⚠️ **表格的每一行都要能唯一区分。** 重排让同一个切分下出现了
两行只差一点的数据，所以方案名里必须标出"加没加重排"。

### 加一种报告格式（比如 HTML）

新建一个类，照着 `ReportRenderer` 写，输入同样是 `DiagnosisReport`。
然后在 `DiagnoseCommand` 里按参数选择用哪个。

## 9. 加命令行参数

**改 1 个文件**：`ragsight-cli/.../DiagnoseCommand.java`

用 picocli 的注解：

```java
@Option(names = {"--my-option"},
        description = "说明文字（默认 ${DEFAULT-VALUE}）",
        defaultValue = "默认值")
private String myOption;
```

⚠️ **参数校验放在 `validateOptions()` 里**，返回非 `null` 表示出错。
所有校验集中在一处，比散在 `run()` 里好读。

⚠️ **报错要给出怎么改，不只是"参数非法"。**
比如缺 Key 的时候，消息里直接给出 Windows 和 Linux 的设置命令。

## 通用检查清单

改完之后过一遍：

- [ ] `mvnw.cmd clean verify` 通过（**注意要 `clean`**）
- [ ] 新增的类有测试，且测试是手算/实测验证过的
- [ ] 没在 `domain` 里引第三方库
- [ ] 没在 `domain` 里用随机数
- [ ] 排序遇到同分时有固定的次级键（保证可复现）
- [ ] `describe()` / `name()` 能唯一区分不同的参数配置
- [ ] 在 `PROGRESS.md` 里记下改了什么、为什么

⚠️ **`clean` 那一条不是形式。** Maven 增量编译不会删除已删除源文件
留下的 `.class`，出现过"源文件明明删了、测试却还在跑"的情况，
排查了很久。加了新文件或者删了文件就更要 `clean`。
