# ADR-004：BM25 放 domain，分词抽成端口

- **状态**：已接受
- **日期**：2026-10-14
- **决策者**：项目发起人

---

## 背景

混合检索需要 BM25（关键词召回）作为向量召回之外的第二路。
它带来一个架构归属问题：

- **BM25 本体是纯算法** —— 词频、逆文档频率、长度归一化，
  给定输入必然得到确定输出。按 ADR-002，这类逻辑属于 domain。
- **但 BM25 需要分词** —— 而分词在实践中往往依赖外部库
  （HanLP / jieba / Lucene Analyzer）。一旦引入，就破坏 R1
  （domain 零第三方运行时依赖），进而破坏"核心算法可在无 API Key
  环境下完整单测"这一根本设计。

两者直接冲突：**算法该在 domain，但算法的前置步骤需要外部依赖。**

---

## 决策

**把分词抽成 domain 的端口，算法留在 domain，实现放 infrastructure。**

```
domain/retrieval/
├── Tokenizer.java        端口：文本 → 词元列表
└── Bm25Scorer.java       纯算法：给定已分词的语料与查询，算 BM25 分数

infrastructure/tokenizer/
├── TextTokenizer.java    切词工具（中文按字、英文按词）
└── SimpleTokenizer.java  实现 Tokenizer 端口
```

**关键约束**：`Bm25Scorer` 接收的是**已经分好词的** `List<List<String>>`，
它自己绝不调用任何分词器。这样 BM25 的数学逻辑在 domain 内保持纯粹，
而"用什么分词器"成为一个可替换的外部决策。

这与 ADR-002 中 `EmbeddingModel` / `VectorIndex` 的处理方式一致：
**把不确定的部分抽成端口，把确定的部分留在内核。**

---

## 理由

### 1. BM25 公式值得被独立验证

BM25 的参数 `k1`（词频饱和）与 `b`（长度归一化）对结果影响很大，
而这两个参数的取值恰恰是诊断报告要给用户的建议。
如果算法被埋在某个带依赖的类里，测试它就得先起一堆外部组件；
放在 domain 则可以对手算结果做精确断言（见 `Bm25ScorerTest`）。

### 2. 分词是可替换的，不该焊死在算法里

按单字切分对中文足够有效；将来若引入专业分词器提升召回，
应当只替换 infrastructure 的一个实现，而不动算法与测试。
这正是端口-适配器的价值。

### 3. 便于把"分词方式"本身作为实验变量

诊断工具的核心能力是消融实验。分词方式（按字 / 按词 / 是否去停用词）
是值得对比的一个维度。端口化之后，它天然成为一个可插拔的实验因子。

---

## 被否决的方案

### 方案 A：BM25 整体放 infrastructure

- ✅ 实现简单，不用抽端口
- ❌ BM25 公式与 `k1`/`b` 参数是**领域知识**，不是基础设施细节。
  放 infrastructure 会让domain 的评估指标（MRR/nDCG 等）无法直接复用
  它的概念，也使这块核心逻辑脱离"零依赖可单测"的保护
- ❌ 违反 ADR-002 建立的"算法在 domain"原则

### 方案 B：BM25 在 domain，直接内置一个分词器

- ❌ 违反 R1（domain 零第三方依赖）
- ❌ 即使内置的是无依赖的简易切词，也会把"分词策略"这个实验变量
  焊死在算法里，无法替换

### 方案 C：不抽端口，让调用方先分好词再传进来（无 Tokenizer 接口）

- ✅ 其实已经解决了依赖问题
- ❌ 但调用方无从知道"该用哪种分词"，且不同调用方可能各写一套，
  导致同一份语料在不同实验里被切得不一样，**实验结果不可比**
- ✅ 最终方案在 C 的基础上补一个 `Tokenizer` 端口来明确契约

---

## 影响

### 正面

- BM25 数学逻辑保持在零依赖环境下可完整单测（含 `k1`/`b` 手算验证）
- 分词策略成为可替换、可实验的独立维度
- 与 `EmbeddingModel` / `VectorIndex` 的处理方式一致，架构风格统一

### 负面 / 代价

- **多一层间接**：调用方需要显式提供 `Tokenizer` 并完成分词
  → 缓解：在 `Bm25Retriever`（infrastructure）里封装这段编排，
    提供一步构建入口，与 `VectorRetriever.indexed()` 对称
- **存在"分词结果与片段顺序错位"的风险**（与向量同款风险）
  → 缓解：`Bm25Scorer` 构造时校验"分词结果数 == 片段数"，
    把这个静默错误在装配阶段拦住
