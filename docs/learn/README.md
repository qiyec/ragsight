# 学 RAG 和 Agent，用这个项目当实验室

这套文档是给**想真正搞懂 RAG 和 Agent** 的人写的，不是给"想用现成框架搭个 demo"的人。

区别在哪：搭 demo 只需要知道"调哪个 API"，搞懂需要知道**为什么这样设计、不这样会怎样**。
后者才能让你在面试里说清一件事，也才能在线上出问题时找到原因。

---

## 这套文档怎么用

**每一篇都有一个能立刻跑的命令。** 不是先读完再动手，而是边跑边看。

跑的前提只有一个：JDK 17。Maven 不用装，仓库里带了。

```bash
git clone https://github.com/qiyec/ragsight.git
cd ragsight
mvnw.cmd clean package -DskipTests     # Windows
./mvnw clean package -DskipTests       # macOS / Linux
```

**不需要 API Key，不需要数据库，不需要联网**（依赖已经在本地仓库的情况下）。
所有实验都在内置的小语料上跑，一次几秒钟。

> 想接真实的向量模型（会明显影响结论），看 [README 里那一节](../README.md#换成真实的向量模型)。
> 但**先别急着接**——前面几篇用离线模式跑就够了，等你看懂指标再接。

## 每篇的结构

| 小节 | 干什么 |
|---|---|
| **这篇解决什么问题** | 一句话说清，不满意就跳过 |

## 这套文档不写什么

- **不写怎么搭一个 RAG 产品。** 那是另一件事，涉及工程、部署、成本。
- **不写 AgentScope 的 API 大全。** 官方文档比我权威，我只讲"为什么这么设计"。
- **不写 LLM 原理。** 注意力机制那些和"怎么诊断检索效果"没关系。

---

## 关于这个项目本身

ragsight 是一个 **RAG 诊断工具**——它不实现检索框架，它量"你的检索到底哪一步不行"。

为什么做这个而不是又一个框架：AgentScope 官方已经有 `agentscope-extensions-rag`
（五种接入方式），再做一个是重复劳动。而"量化诊断"这件事没人做。

完整说明见 [README](../../README.md)，技术细节见 [docs/design](../design/)。
